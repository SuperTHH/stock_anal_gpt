## 2. 产品背景

### 2.1 问题

个人投资者在 A 股收市后进行中长期研究时，需要同时处理日线行情、交易状态、公司行动、财务报表、公告、监管事件和宏观数据。公开数据来源分散，发布时间与生效时间不同，财务数据可能更正，来源条款也不允许任意保存全文。直接依赖商业财经网站容易产生许可不清、数据无法追溯、未来数据泄漏和不完整结论等问题。

本产品需要在每日收市后，把允许自动获取的公开数据整理为可追溯的本地研究快照，并建立三个互相独立的候选池，帮助用户发现值得继续研究的股票，而不是替用户下达买入指令。

### 2.2 产品目标

P0 目标：

1. 初始化并持续维护近五年 A 股研究数据。
2. 每个交易日 21:30 自动执行增量更新和分析。
3. 对每条事实保留来源、发布时间、生效时间、采集时间、版本和质量状态。
4. 分别生成“质量成长合理估值”“低估值价值”“稳定高股息”三个候选池。
5. 为候选股票提供财务、估值、催化剂、风险、观察条件和失效条件。
6. 在关键数据缺失或质量校验失败时阻断候选榜，保留上一有效报告。
7. 通过五个本地只读页面完成每日复盘和来源追溯。

### 2.3 成功标准

| 编号 | 指标 | MVP 标准 |
| --- | --- | --- |
| KPI-01 | 报告可追溯率 | 页面展示的事实和指标 100% 可打开来源记录 |
| KPI-02 | 未来数据泄漏 | 固定回测测试集为 0 条 |
| KPI-03 | 不完整榜单 | 关键数据缺失时输出数量为 0 |
| KPI-04 | 任务幂等性 | 同一交易日重复执行不产生重复事实或重复报告 |
| KPI-05 | 正常发布时间 | 数据源正常时 22:00 前完成报告发布 |
| KPI-06 | 降级可靠性 | 任务失败后上一有效报告保持可读并明确标记未更新 |
| KPI-07 | 合规拒绝 | 非白名单域名、商业媒体正文和未授权附件拒绝率 100% |
| KPI-08 | 页面可用性 | 1440、1280、1100 px 无横向溢出 |

## 3. 用户与使用场景

### 3.1 目标用户

首版只有一个角色：本地个人研究者。

用户能够：

- 配置允许使用的数据源凭证；
- 查看本地研究报告和来源；
- 维护个人观察状态和研究备忘录；
- 手动重试失败任务；
- 导出结构化研究快照。

用户不能通过本产品：

- 自动下单；
- 自动生成确定性买入建议；
- 向外部用户开放公共查询 API；
- 绕过网站访问限制、验证码、登录或付费权限；
- 保存无授权商业媒体全文。

### 3.2 核心场景

#### 场景 S1：每日收市后复盘

用户在 22:00 后打开“每日研究总览”，确认报告日期、数据完整度、市场概况、官方事件和三个策略池状态。如果报告未更新，用户能看到失败阶段、缺失数据和上一有效版本。

#### 场景 S2：筛选中长期候选

用户进入某一策略池，只在该策略内部筛选和排序。用户查看入选理由、因子、风险、观察条件和失效条件后进入个股研究。三个策略不产生共享名次或跨策略总分。

#### 场景 S3：验证个股研究论点

用户查看五年财务质量、估值、资产负债、股东回报和事件催化剂，并通过来源抽屉验证每个事实。用户记录证据、反证和后续检查点，但系统不输出目标价或交易动作。

#### 场景 S4：跟踪官方事件

用户查看交易所、证监会、国家统计局和上市公司公告形成的官方事件流。页面分离官方事实和系统研判，并允许筛选与半年以上持有期相关的事件。

#### 场景 S5：排查数据问题

用户进入“数据质量与来源”，定位采集失败、财务缺失、版本冲突、复权异常或条款待复核问题，并查看它们阻断了哪些指标、股票和策略池。

MVP 覆盖完整本地产品：

## 5. 关键业务原则

### BR-001 研究边界

系统只输出研究候选、证据、风险和观察条件。页面、导出文件和接口不得出现“自动买入”“强烈推荐”“目标价”“稳赚”或确定性收益描述。

### BR-002 策略独立

三个策略池使用不同指标、权重和排名。允许同一股票进入多个池，但必须保留独立的入选原因和策略内分数。禁止创建跨策略总分和统一总榜。

### BR-003 真实与演示隔离

生产数据不得显示演示水印。功能演示环境中的候选池和个股研究必须固定显示：

`功能演示数据 · 虚构标的 · 非实时`

演示数据不得进入生产覆盖率、事件数量、任务状态、策略统计和结论。

### BR-004 当时可知

任何日期的报告和回测只能读取该报告截止时间前已公开的版本。后续更正不能覆盖历史版本，也不能改变过去已发布报告。

### BR-005 不完整即阻断

日线、证券状态、最新可用财务事实、公司行动复权或当时可知校验任一关键域不满足发布门槛时，系统不得发布新的候选榜。

### BR-006 原始数据不可变

采集到的原始响应、文件哈希和原始价格不得被后续清洗或更正覆盖。标准化记录和派生数据以新版本写入。

### BR-007 合规优先

采集器只能访问启用且复核有效的白名单来源。不得调用隐藏接口、绕过验证码、模拟付费权限、突破频率限制或自动抓取禁止保存的正文。

### BR-008 来源可追溯

每条事实和派生指标必须能追溯到一个或多个来源记录。无法追溯的数值不得出现在生产研究结论中。

### BR-009 失败不补猜

缺失字段显示“数据不足”“未记录”“未核实”或“未更新”。系统不得插值伪装财务事实，不得使用大模型常识补齐数值，也不得切换至许可不明来源。

### BR-010 本地只读

首版页面只通过本机回环地址访问。研究数据 API 对浏览器只开放读取；采集、重算和重试通过本地受控任务执行。

### 6.2 禁止自动获取

P0 拒绝以下来源或内容：

- 东方财富、第一财经、证券时报、股吧、雪球等商业媒体或社区正文；
- 未经明确授权的中国货币网数据和北交所行情；
- 未核实转载条款的人民银行及其他政府页面正文；
- 非白名单域名、短链接跳转到非白名单的页面；
- robots、访问控制、验证码或频率限制明确阻止的内容；
- 登录后、付费后或依赖非公开接口才能取得的内容；
- 与研究无关的大体积附件和可执行文件。

商业新闻可以由用户手动打开，但系统不得采集正文。未来接入授权新闻服务必须新增 `SourcePolicy`、许可证据和独立验收。

### 6.3 SourcePolicy 管理

每个来源必须配置：

- `source_id`
- `source_name`
- `allowed_domains`
- `allowed_schemes`
- `allowed_purposes`
- `fetch_frequency`
- `full_text_rule`
- `attachment_rule`
- `rate_limit`
- `robots_policy`
- `terms_url`
- `terms_reviewed_at`
- `review_status`
- `connection_status`
- `enabled`

规则：

1. `review_status` 不是 `APPROVED` 时不得自动采集。
2. 没有书面复核日期时显示“未记录”，不得用开发日期代替。
3. 条款内容或入口发生变化时，来源自动进入 `REVIEW_REQUIRED`，暂停新增采集。
4. 每次网络请求在发送前经过策略守卫；拒绝请求写入 `RefusalRecord`。
5. 页面必须展示当前连接状态和官方链接。
6. 协议必须在 `allowed_schemes` 中逐来源批准。Tushare REST API 仅对官方文档指定的 `http://api.tushare.pro` 允许 HTTP；其他 MVP 自动来源默认只允许 HTTPS。

### 6.4 访问频率与礼貌采集

- 同一域名并发数默认为 1。
- 请求间隔、每日上限和重试规则由 `SourcePolicy` 配置，不在采集器中硬编码。
- 遇到 HTTP 401、403、429、验证码或访问限制时停止该来源任务，不通过代理、UA 轮换或其他方式规避。
- 单次失败采用有限重试；持续失败转为数据缺失并触发降级。
- 下载文件前检查 Content-Type、Content-Length 和允许的扩展名。

## 7. 系统架构与模块边界

### 7.1 逻辑架构

系统分为九个独立模块：

1. **Policy Guard**：判断来源、域名、用途、频率和保存方式是否允许。
2. **Collectors**：按来源获取原始响应、文件和请求元数据。
3. **Raw Store**：按内容哈希不可变保存原始数据。
4. **Normalizers**：将来源字段映射为统一数据契约。
5. **Versioned Warehouse**：保存证券、行情、财务、事件和公司行动的历史版本。
6. **Quality & Point-in-Time Engine**：质量校验、冲突处理和当时可知查询。
7. **Factor & Strategy Engine**：计算派生指标并生成三个独立候选池。
8. **Report Publisher**：生成原子化日报快照，失败时保留上一版。
9. **Local Read-only Web**：提供五个页面、来源抽屉和本地查询接口。

模块之间只通过明确数据契约交互。采集器不得直接写策略结果；页面不得直接读取未经质量校验的原始数据。

### 7.2 推荐实现架构

以下是 MVP 的推荐实现，不改变业务验收标准：

- Python 3.12：采集、解析、质量校验、策略和任务 CLI；
- SQLite：本地轻量事务存储，保存 `SourcePolicy`、`RunRecord`、`RefusalRecord`、报告索引、研究备忘录和应用设置；
- DuckDB：本地分析查询和版本化事实表；
- Parquet：不可变原始与标准化分区文件；
- FastAPI：仅绑定 `127.0.0.1` 的只读本地接口；
- React + TypeScript：五页面研究界面；
- Windows Task Scheduler：每天 21:30 调用任务 CLI；
- Pytest：数据、策略和任务测试；
- Playwright：页面交互和 1440/1280/1100 响应式验收。

允许替换技术组件，但必须保留模块边界、数据契约、幂等性、当时可知和原子发布要求。

## 8. 数据契约

### 8.1 通用字段

除来源政策外，所有事实类型至少包含：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `record_id` | string | 稳定唯一标识 |
| `source_id` | string | 关联 `SourcePolicy` |
| `source_url` | string | 最终官方原文或下载地址 |
| `published_at` | datetime nullable | 来源公开时间；未知时为空并标记质量状态 |
| `effective_at` | datetime nullable | 业务生效时间 |
| `collected_at` | datetime | 实际采集时间，Asia/Shanghai |
| `version` | string | 来源版本或系统生成版本 |
| `content_hash` | string | 原始内容 SHA-256 |
| `license_policy` | string | 许可规则标识 |
| `quality_status` | enum | 见 8.12 |
| `supersedes_id` | string nullable | 被当前版本替代的记录 |
| `valid_from` | datetime | 该版本进入系统可见状态的时间 |

未知数据必须使用 `null` 和质量状态表达，禁止用虚构时间、`0` 或空字符串代替。

### 8.2 SecurityMaster

- `ts_code`
- `symbol`
- `name`
- `exchange`
- `board`
- `currency`

## 9. 数据处理流程

### 9.1 近五年初始化

初始化按以下顺序执行并支持断点续传：

1. 来源政策预检；
2. 证券主数据和交易日历；
3. 当前在市股票最近财务报告；
4. 最近一年行情、状态和公司行动；
5. 最近官方事件；
6. 扩展至近五年行情；
7. 补齐五年财务事实、公告和更正；
8. 计算复权、总回报和因子；
9. 运行全量质量校验；
10. 满足发布门槛后生成首份生产报告。

初始化未完成时，页面显示进度和缺失域，不输出真实候选榜。初始化耗时可以超过一个自然日，但每个阶段必须可恢复且不得重复写入。

### 9.2 每日增量任务

交易日 21:30，Asia/Shanghai，依次执行：

1. 检查交易日和 SourcePolicy；
2. 按交易日期调用一次 Tushare `daily`；
3. 更新证券状态、停复牌和 ST 信息；
4. 获取当日公司行动和公告；
5. 获取监管、交易所和宏观官方事件；
6. 更新新发布或更正的财务事实；
7. 执行结构、范围、重复、冲突和时效校验；
8. 重算受影响复权区间和派生因子；
9. 固化当时可知数据视图；
10. 运行通用硬过滤和三个策略；
11. 生成报告快照和页面数据；
12. 原子切换 `latest` 指针；
13. 记录运行结果并触发本地告警。

### 9.3 幂等与重复处理

- 每个采集任务的幂等键为 `source_id + data_type + business_date + request_variant`。
- 相同内容哈希不重复保存附件。
- 相同唯一键和版本重复到达时记录命中，不新增事实。
- 内容变化但来源版本不变时生成系统子版本并标记 `CONFLICT`，等待规则或人工确认。
- 每日任务可安全重跑，只有满足 `PUBLISHED` 或 `PUBLISHED_PARTIAL` 对应发布门槛的完整报告包能够成为 `latest`。

### 9.4 当时可知规则

正常每日任务的 `report_cutoff_at` 为报告交易日 21:30:00，Asia/Shanghai，即任务开始时间。行情业务日期仍为当日交易日；官方事件只纳入 21:30 前已公开的内容，21:30 后发布的事件进入下一份报告。

历史补录任务可以使用交易日 23:59:59 作为事件截止时间，但必须在 `ReportSnapshot` 中保存实际截止值，不得让补录结果覆盖当日 21:30 已发布版本。`generation_cutoff_at` 为本次报告生成任务的实际开始时间。

可用于报告的事实必须同时满足：

- `published_at` 为空时不能进入依赖发布时间的策略计算；
- `published_at <= report_cutoff_at`；
- `valid_from <= generation_cutoff_at`；
- 该版本在报告截止时未被一个同样已公开的更正版本替代。

历史回放必须指定 `as_of`，查询层不得默认读取最新财务版本。更正文件只影响其公开时间之后的报告。

### 9.5 复权和总回报

- 保留未复权 OHLC。
- 使用官方现金分红、送转、拆并股和配股记录计算复权因子。
- 前复权、后复权和总回报序列均为派生数据，记录算法版本和公司行动来源。
- 除权除息日前后总回报应连续；原始价格不得被修改。
- 公司行动缺失、顺序冲突或数值异常时，该股票的收益类因子标记为 `UNVERIFIED`，并阻断依赖这些因子的候选资格。

### 9.6 财务更正

- 定期报告、业绩预告和更正公告分别保留。
- 更正版本使用 `supersedes_id` 指向被替代版本。
- 最新研究页显示截止当前的有效版本；历史报告显示当时版本。
- XBRL 与 PDF 数值冲突时优先展示 XBRL，并将冲突写入质量问题；冲突未解决前不得用于策略排名。

## 10. 策略与分析需求

### 10.1 通用硬过滤

在三个策略计算前，股票必须通过以下 P0 过滤：

| 编号 | 过滤条件 | 默认规则 |
| --- | --- | --- |
| HF-01 | 市场范围 | 仅沪深主板、创业板、科创板 A 股 |
| HF-02 | 退市风险 | 排除退市整理、已公告终止上市和重大退市风险 |
| HF-03 | ST | 排除 ST、*ST 和其他特别处理 |
| HF-04 | 停牌 | 报告日停牌或无法形成有效收盘数据时排除 |
| HF-05 | 上市时间 | 上市不足 365 个自然日排除 |
| HF-06 | 流动性 | 近 60 个有效交易日日均成交额低于 5000 万元排除 |
| HF-07 | 审计意见 | 最近年度报告为非标准无保留意见时排除 |
| HF-08 | 重大调查 | 公司或关键责任主体存在未结重大立案调查时排除 |
| HF-09 | 财务完整度 | 策略所需关键财务字段完整度低于 85% 排除 |
| HF-10 | 复权质量 | 公司行动或总回报校验未通过时排除 |
| HF-11 | 当时可知 | 无法确定公开时间或版本顺序的关键事实排除 |
| HF-12 | 数据时效 | 最新可用财务报告超过策略允许时效时排除 |

默认阈值必须配置化并带 `filter_version`。阈值变化只影响新报告，不改写历史报告。

### 10.2 因子标准化

- 因子在同一策略版本内计算。
- 估值、盈利和成长因子优先在一级行业内计算百分位；行业有效样本少于 20 时回退到全市场并标记回退。
- 极端值采用 1%/99% 缩尾，但原始数值保留并可追溯。
- 正向因子百分位越高得分越高；负向因子反向计分。
- 关键因子缺失时不允许静默重分配权重。
- 非关键因子缺失时可以计算，但必须降低完整度和置信度，并在因子明细中标识。
- 候选池默认最多输出 30 只；不足 30 只时显示实际数量，不补齐。

### 10.3 质量成长合理估值

策略目标：寻找资本回报较好、成长可持续、现金流能验证利润且估值未明显透支的公司。

默认策略内权重：

| 因子组 | 权重 | 主要指标 |
| --- | ---: | --- |
| 资本回报 | 20% | ROE、ROIC、ROIC 三年趋势 |
| 成长质量 | 20% | 营收三年复合增长、扣非利润三年复合增长、增长稳定性 |
| 现金流质量 | 20% | 经营现金流/扣非利润、自由现金流、应收与存货变化 |
| 盈利稳定性 | 10% | 毛利率波动、净利率波动 |
| 资产负债 | 10% | 负债率、净现金、利息保障 |
| 合理估值 | 20% | PE、PB、EV/EBITDA 的历史与行业分位 |

策略输出必须解释：

- 哪些资本回报和成长指标支持入选；
- 现金流是否验证利润；
- 当前估值相对历史和行业的位置；
- 半年以上的潜在催化剂；
- 客户集中、扩产、需求和竞争等风险；
- 可量化的观察条件和失效条件。

### 10.4 低估值价值

策略目标：寻找相对自身历史和行业存在折价、资产质量可接受且价值陷阱风险可控的公司。

默认策略内权重：

| 因子组 | 权重 | 主要指标 |
| --- | ---: | --- |
| 绝对估值 | 25% | PE、PB、EV/EBITDA、FCF 收益率 |
| 相对估值 | 20% | 历史估值分位、行业估值分位 |
| 资产质量 | 20% | 净资产质量、应收、存货、减值、商誉 |
| 现金流与负债 | 15% | 自由现金流、净负债、短期偿债 |
| 周期位置 | 10% | 收入、价格、产能利用率或行业周期代理指标 |
| 价值陷阱风险 | 10% | 盈利恶化、治理、资本开支、持续低回报 |

PE 为负或不具经济意义时不得按低 PE 加分，必须使用适用的资产、现金流和周期指标。周期位置数据不足时，候选状态最多为 `WATCH`。

### 10.5 稳定高股息

策略目标：寻找分红记录稳定、现金流能够覆盖派息且资产负债表能承受周期波动的公司。

默认策略内权重：

| 因子组 | 权重 | 主要指标 |
| --- | ---: | --- |
| 股息率 | 25% | 基于已公告现金分红和报告日价格计算 |
| 连续性 | 20% | 连续分红年限、削减次数 |
| 派息合理性 | 15% | 派息率、盈利波动下的可持续性 |
| 现金流覆盖 | 20% | 自由现金流/现金分红、经营现金流稳定性 |
| 资产负债 | 10% | 净负债、利息保障、短期偿债 |
| 分红削减风险 | 10% | 盈利下降、资本开支、监管和周期风险 |

不得使用尚未公告的预测分红计算生产股息率。一次性特别分红必须单独标识，不得与常规股息率混合。

### 10.6 排名与入选

每个策略独立执行：

1. 通用硬过滤；
2. 策略必要条件；
3. 因子计算和质量校验；
4. 策略内加权得分；
5. 风险标记和置信度调整；
6. 生成策略内排名；
7. 输出最多 30 只 `CANDIDATE` 或 `WATCH`。

`strategy_score` 保留两位小数，仅用于策略内部排序。页面必须同时展示因子明细，不得让单一分数替代研究证据。

### 10.7 观察条件和失效条件

- 观察条件必须是后续可验证的事实，例如连续两个季度现金流覆盖、良率达到阈值或估值进入区间。
- 失效条件必须能够否定核心论点，例如 ROIC 连续两期跌破阈值、应收增速显著高于收入或分红覆盖不足。
- 自动生成的文本只能基于结构化事实和规则模板。
- 大模型可以改写摘要，但不得创造财务数值、公司事件或来源；改写结果必须保留事实引用。

## 11. 信息架构与导航

主研究路径：

`每日研究总览 → 策略候选池 → 个股研究`

支持页面：

- 官方事件流；
- 数据质量与来源；
- 全局来源抽屉。

所有页面共用：

- 左侧固定导航；
- 报告日期和数据状态；
- 全局证券搜索；
- 来源追溯入口；
- “仅供个人研究，不构成投资建议”；
- 当前报告版本和数据截止时间。

从候选池进入个股研究时保存策略页签、筛选条件、排序、选中行和滚动位置。返回时恢复上下文；无浏览历史时回退到候选池默认入口。

## 12. 页面需求

### 12.1 每日研究总览

#### 目的

让用户在一分钟内判断本期报告是否可用、市场数据是否完整、三个策略是否生成，以及哪些官方事件值得进一步查看。

#### P0 内容

- 报告日期、采集日期、生成时间和报告状态；
- 市场概况：上证指数、沪市成交额、深市成交额、全市场成交额、在市数量和总市值；
- 三个独立策略模块及候选数量；
- 官方事件摘要；
- 数据质量和阻断原因；
- 上一有效报告入口；
- 任务失败时的“本期未更新”标记。

#### 规则

- 无法可靠确认的市场指标不展示。
- 策略关键数据缺失时显示阻断态，不显示示例候选。
- 每个派生市场值标注计算口径。
- 点击指标或状态打开来源抽屉。

### 12.2 策略候选池

#### P0 内容

- 三个互斥策略页签；
- 当前报告日期、策略版本、候选数量和数据状态；
- 行业、市值、流动性、风险、完整度和观察状态筛选；
- 策略内排序；
- 候选表格和选中候选证据面板；
- 入选理由、因子、风险、催化剂、观察条件和失效条件；
- 进入个股研究操作。

#### 规则

- 筛选和排序只作用于当前策略。
- 切换策略后不得沿用不适用的排序字段。
- 同一股票在不同策略中显示独立分数和理由。
- 不显示跨策略排名、总分或自动买入状态。
- 功能演示环境必须持续显示演示水印。

### 12.3 个股研究

#### P0 内容

- 股票名称、代码、行业、所属策略、研究日期和数据状态；
- 入选理由、半年以上催化剂、主要风险、观察条件和失效条件；
- 五年财务质量；
- 估值及历史、行业分位；
- 资产负债与营运质量；
- 股东回报和现金流覆盖；
- 官方公告和公司事件时间线；
- 研究备忘录；
- 统一来源抽屉；
- 返回候选池并恢复上下文。

#### 图表规则

- 财务图表显示分析窗口、截止时间、单位和版本。
- 原始价格与复权或总回报必须清楚区分。
- 缺失数据留下空档并标记，不做视觉插值。
- 颜色不能单独表达状态。
- 功能演示环境只使用虚构公司和演示公司事件。

#### 研究备忘录

备忘录为唯一允许写入的页面区域，字段包括：

- 当前论点；
- 支持证据；
- 反证；
- 后续检查点；
- 用户观察状态；
- 更新时间。

备忘录与事实数据库隔离，不参与策略得分。

### 12.4 官方事件流

#### P0 内容

- 事件截止时间、采集时间和来源覆盖；
- 来源、类型、日期、影响周期、置信度和影响对象筛选；
- 按发布时间倒序的时间线；
- 官方事实与系统研判分区；
- 可能传导链、相关策略和观察数据；
- 原文链接和完整时间元数据；
- “仅看事实/显示系统研判”和“半年以上相关”开关。

#### 规则

- 官方事实不得包含来源未陈述的结论。
- 系统研判不得预测确定性涨跌。
- 事件可以关联行业和策略，不能生成个股交易建议。
- 当天无新增事件时显示真实空状态，不以商业新闻填充。
- 未记录的时间或许可字段显示“未记录”或“未核实”。

### 12.5 数据质量与来源

#### P0 内容

- 报告日期、采集日期和整体状态；
- 七个数据域状态；
- SourcePolicy 登记表；
- 来源连接状态和官方链接；
- 数据血缘；
- 21:30 运行记录、失败原因、重试和下次计划；
- 拒绝记录；
- 来源追溯检查器；
- 被质量问题影响的页面、指标和策略。

七个数据域：

1. 交易所市场概览；
2. 官方事件流；
3. 全市场日线；
4. 财务事实/XBRL；
5. 公司行动与复权；
6. 当时可知校验；
7. 三个策略候选池。

#### 规则

- 不显示综合质量分或虚构覆盖率。
- 功能演示数据不得进入该页面。
- 状态必须同时使用文字、图标和颜色中的至少两种表达。
- 质量问题必须展示影响范围和建议处理动作。

### 12.6 统一来源抽屉

从指标、图表、事件或质量记录打开，显示：

- 来源名称；
- 原文链接；
- 发布时间；
- 生效时间；
- 采集时间；
- 版本；
- 许可政策；
- 质量状态；
- 原始内容哈希；
- 派生公式及上游记录。

演示数据的来源名称固定为“功能演示数据集”，不伪造真实 URL。

### 12.7 搜索

- 支持按六位代码、交易所后缀和证券简称搜索。
- 只返回范围内证券。
- 已退市证券可以在历史报告中查到，但不进入当期候选。
- 搜索结果显示证券状态和最近有效报告日期。

## 14. 调度、发布与降级

### 14.1 调度

- 时区固定为 `Asia/Shanghai`。
- 每个交易日 21:30 启动每日任务。
- 非交易日写入 `NOT_A_TRADING_DAY` 运行记录，不生成新报告。
- 交易日历不可用时不猜测是否开市，任务进入 `BLOCKED`。
- Windows Task Scheduler 调用单一 CLI 入口，并传入交易日、运行类型和配置文件。

### 14.2 重试

- 网络和临时服务错误默认在 5、15、30 分钟后重试。
- 数据格式、策略校验、401、403、429、验证码和政策拒绝不进行无限重试。
- 23:30 前仍未满足发布门槛时结束当期任务并保留上一报告。
- 用户手动重试生成新的 `run_id`，但复用相同幂等键。

### 14.3 发布门槛

新报告只有同时满足以下条件才能标记 `PUBLISHED`：

1. 证券范围和交易状态完成；
2. 全市场日线记录数、价格范围和重复检查通过；
3. 具备基础财务事实的可计算股票覆盖率达到 95%，且每只候选的策略关键字段完整度达到 85%；
4. 公司行动和复权检查通过；
5. 当时可知测试通过；
6. 三个策略独立完成；
7. 报告清单和内容哈希生成成功。

如果市场概况或官方事件可用，但策略关键域缺失，可以发布不含候选榜的 `PUBLISHED_PARTIAL` 研究总览；页面必须显示“策略输出阻断”，不得把该状态视为完整日报。

### 14.4 原子发布

- 报告先写入临时版本目录。
- 数据文件、清单、页面查询和来源索引全部校验通过后，原子更新 `latest` 指针。
- 发布失败时删除不完整临时引用，但保留错误日志和已采集原始文件。
- 已发布版本不覆盖，用户可以切换到历史报告。

### 14.5 本地告警

MVP 使用本地系统通知和页面告警，不发送外部邮件或即时消息。告警级别：

- `INFO`：任务完成、非交易日；
- `WARNING`：单一非关键来源失败、报告使用上一版本；
- `ERROR`：关键数据缺失、候选榜阻断、复权或版本校验失败；
- `POLICY`：来源条款待复核、域名或附件被拒绝。

## 15. 本地查询接口

首版不开放公共 API。以下接口仅绑定本机回环地址，默认只读：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/v1/reports/latest` | 最新报告元数据和状态 |
| `GET /api/v1/reports/{report_id}` | 指定历史报告 |
| `GET /api/v1/strategies/{strategy_type}/candidates` | 指定报告的策略候选 |
| `GET /api/v1/securities/{ts_code}/research` | 个股研究事实和策略上下文 |
| `GET /api/v1/events` | 官方事件筛选查询 |
| `GET /api/v1/quality` | 数据域、来源和运行状态 |
| `GET /api/v1/lineage/{entity_type}/{record_id}` | 来源和数据血缘 |
| `GET /api/v1/search/securities` | 证券搜索 |
| `GET /api/v1/config/public` | 非敏感显示配置 |

研究备忘录使用独立本地接口：

- `GET /api/v1/notes/{ts_code}`
- `PUT /api/v1/notes/{ts_code}`

写入接口只允许修改备忘录，不得修改行情、财务、事件、策略或报告事实。

通用接口响应必须包含：

- `data`
- `report_id`
- `as_of`
- `quality_status`
- `lineage_available`
- `error`

错误不得只返回 HTTP 状态码，必须提供稳定 `error_code` 和用户可理解的中文摘要。

## 16. 非功能需求

### 16.1 性能

- 本地缓存命中时，五个主页面首屏 P95 小于 2 秒。
- 30 只候选的筛选和排序 P95 小于 300 毫秒。
- 来源抽屉 P95 小于 500 毫秒。
- 正常增量任务不含外部等待的本地处理时间小于 30 分钟。
- 五年初始化允许分阶段超过 24 小时，但必须支持恢复和进度显示。

### 16.2 可靠性

- 重复运行不产生重复数据。
- 任一阶段异常不得破坏上一有效报告。
- 应用重启后能够恢复未完成初始化和可重试任务。
- 数据库、Parquet 和报告清单之间存在一致性校验。
- 每次发布保存可复现的策略、过滤器和算法版本。

### 16.3 安全

- Tushare Token 只从环境变量或本地密钥存储读取。
- Token、Cookie 和个人凭证不得写入日志、数据库、报告或 Git。
- API 默认绑定 `127.0.0.1`，不监听公网网卡。
- 下载附件进行类型、大小、扩展名和哈希检查；不自动执行宏、脚本或二进制文件。
- 页面输出对公告文本和用户备忘录进行 HTML 转义。
- 所有文件访问限制在配置的数据目录内，拒绝路径穿越。

### 16.4 可审计性

- 任务、政策判断、拒绝、版本更正、策略计算和报告发布均有审计记录。
- 任何页面数值能定位到 `record_id` 或派生公式。
- 审计日志至少保留五年或与历史库等长。
- 清理原始附件前必须确认其未被任何已发布报告引用。

### 16.5 可维护性

- 来源适配器、解析器、质量规则和策略版本独立。
- 策略参数使用版本化配置，不散落在页面或 SQL 中。
- 数据契约变更必须有迁移脚本和兼容性测试。
- 每个模块包含单元测试；跨模块流程包含固定快照集成测试。
- 中文用户文案和状态枚举集中管理。

## 17. 数据质量规则

### 17.1 行情

- `high >= max(open, close, low)`；
- `low <= min(open, close, high)`；
- 价格、成交量和成交额不得为非法负值；
- `pre_close` 与上一有效交易日 `close` 的关系可解释；
- 同一证券交易日不得出现未解决重复记录；
- 全市场记录数与在市、停牌状态基本一致，偏差超过配置阈值时阻断。

### 17.2 财务

- 会计期间、单位、币种和合并口径明确；
- 资产负债表满足基本恒等检查；
- 现金流和利润单位一致；
- 同一事实的 XBRL、PDF 和更正版本关系可解释；
- 同比、复合增长率和比率的分母为零时返回缺失状态，不返回无穷大；
- 报告期和公告时间不得颠倒。

### 17.3 公司行动

- 除权日顺序合法；
- 现金分红、送转和配股参数处于合理范围；
- 总回报连续性测试通过；
- 原始价格哈希在重算前后保持不变。

### 17.4 事件

- 来源机构、标题、发布时间和原文链接至少三项可验证；
- 官方事实与系统研判分字段保存；
- 研判必须包含影响周期和置信度；
- 商业媒体域名不得进入事件原文链接。

### 17.5 发布阻断矩阵

| 数据域 | 缺失时市场总览 | 缺失时候选池 | 缺失时个股研究 |
| --- | --- | --- | --- |
| 交易所市场概况 | 可发布降级态 | 不直接阻断 | 不直接阻断 |
| 全市场日线 | 显示缺失 | 阻断全部策略 | 价格与估值模块阻断 |
| 交易状态 | 显示缺失 | 阻断全部策略 | 显示状态未知 |
| 财务事实 | 显示缺失 | 阻断受影响股票；覆盖不足时阻断策略 | 财务和策略结论阻断 |
| 公司行动/复权 | 显示待验证 | 阻断收益相关策略资格 | 收益图表阻断 |
| 官方事件 | 可发布并显示缺失 | 不阻断因子排名 | 事件模块降级 |
| 当时可知校验 | 显示失败 | 阻断全部策略 | 历史研究阻断 |

## 18. 验收标准

### 18.1 合规验收

- AC-C01：非白名单域名在请求发出前被拒绝，并产生 `RefusalRecord`。
- AC-C02：商业媒体正文和未授权附件不进入 Raw Store。
- AC-C03：401、403、429 和验证码不会触发绕过行为。
- AC-C04：所有生产来源都有可见的 `SourcePolicy`、官方链接和复核状态。
- AC-C05：Token 不出现在 Git、日志、数据库和接口响应中。

### 18.2 采集与版本验收

- AC-D01：Tushare 日线按交易日一次获取全市场数据，不逐股票循环。
- AC-D02：停牌、缺失和重复记录得到可解释状态。
- AC-D03：同一交易日任务重复执行两次，事实数量和最新报告数量不增加。
- AC-D04：财务更正追加新版本，历史版本仍可查询。
- AC-D05：原始附件按哈希去重，来源请求元数据保留。

### 18.3 当时可知与复权验收

- AC-P01：在更正公告发布前的回测日期只能读取旧财务版本。
- AC-P02：未来公告、未来生效公司行动和未来采集结果不会进入历史报告。
- AC-P03：分红送转前后总回报连续，原始 OHLC 哈希不变。
- AC-P04：公司行动缺失时收益因子进入阻断，不使用付费复权数据补齐。

### 18.4 策略验收

- AC-S01：三个策略使用独立权重、独立排名和独立候选集合。
- AC-S02：系统不存在跨策略总分或总榜接口。
- AC-S03：ST、停牌、上市不足一年、低流动性、非标审计、重大调查和严重缺失股票被过滤。
- AC-S04：PE 为负的股票不会因“低 PE”获得价值策略加分。
- AC-S05：候选输出包含理由、因子、风险、催化剂、观察条件、失效条件和完整度。
- AC-S06：关键数据缺失时不输出不完整候选榜。
- AC-S07：策略版本和阈值变化不改写历史排名。

### 18.5 任务与降级验收

- AC-R01：交易日 21:30 触发任务，非交易日记录跳过状态。
- AC-R02：任务失败时上一有效报告继续可读并标记“本期未更新”。
- AC-R03：临时报告校验失败时 `latest` 指针不变化。
- AC-R04：重试次数、失败阶段和下次计划时间在质量页可见。
- AC-R05：Tushare 免费规则或权限变化时停止更新并告警，不切换到条款不明来源。

### 18.6 页面验收

- AC-U01：五个页面和统一来源抽屉可通过本地只读接口加载。
- AC-U02：1440、1280、1100 px 的 `scrollWidth` 不超过视口宽度。
- AC-U03：候选池返回上下文包含策略、筛选、排序和滚动位置。
- AC-U04：页面事实均显示来源、发布时间、采集时间、版本和质量状态。
- AC-U05：演示候选和个股页持续显示明确水印，真实页面无演示水印。
- AC-U06：页面不存在买入指令、目标价、收益承诺和商业新闻正文。
- AC-U07：数据质量页不显示综合质量分或虚构覆盖率。
- AC-U08：无事件、字段缺失、任务失败和报告过期都有明确空状态或降级状态。

### 18.7 性能与安全验收

- AC-N01：本地页面和筛选达到 16.1 的 P95 指标。
- AC-N02：API 不监听非回环地址。
- AC-N03：恶意 HTML、路径穿越和超限附件测试被拒绝。
- AC-N04：应用重启后能够恢复初始化进度。
- AC-N05：发布清单哈希能够发现文件篡改或不一致。

## 21. 大模型开发附录

### 21.1 不可违反的开发规则

后续大模型必须遵守：

1. 不发明股票、财务、行情、公告、时间和来源数据。
2. 不添加白名单以外的数据源。
3. 不调用隐藏接口，不绕过验证码、频率、登录或付费限制。
4. 不覆盖原始数据和历史财务版本。
5. 不让历史查询默认读取最新版本。
6. 不在关键数据缺失时生成候选榜。
7. 不合并三个策略分数。
8. 不生成交易指令、目标价或确定性收益。
9. 不把演示数据写入生产数据域。
10. 不在日志、测试快照和提交中暴露 Token。

### 21.2 开发任务顺序

大模型应按依赖顺序开发：

1. 数据契约与状态枚举；
2. SourcePolicy 与 Policy Guard；
3. Raw Store 和审计；
4. 证券主数据和日线；
5. 财务事实和公司行动；
6. 质量校验和当时可知查询；
7. 复权与因子；
8. 三个独立策略；
9. 任务编排和原子发布；
10. 本地 API；
11. 五页面和来源抽屉；
12. 故障注入、端到端验收和运行文档。

每一步必须先写失败测试，再实现最小功能，运行对应测试，通过代码审查后进入下一步。

### 21.3 模块完成定义

一个模块只有同时满足以下条件才算完成：

- 接口和类型与本 PRD 一致；
- 正常、缺失、冲突、重复和拒绝路径有测试；
- 日志不包含敏感信息；
- 事实能够追溯来源；
- 失败不会破坏已发布报告；
- 文档说明如何本地运行和验证；
- 没有未说明的占位逻辑或静默回退；
- `git diff --check`、单元测试、集成测试和相关端到端测试通过。

### 21.4 大模型实现提示模板

后续可以把本 PRD 与单一里程碑一起交给大模型。以下是实现 `M1：数据底座` 时可直接使用的示例：

```text
以 docs/product/2026-07-24-a-share-long-term-research-platform-prd.md 为最高需求基线。
本次只实现里程碑 M1：数据底座，不要提前实现后续里程碑。
先读取相关数据契约、业务规则、验收编号和现有测试。
列出将创建或修改的文件、模块输入输出和失败模式。
采用测试驱动开发：先证明测试在缺少功能时失败，再实现，再运行完整相关测试。

```

实现后续里程碑时，只替换示例中的里程碑编号和名称，其他约束继续生效。

### 21.5 决策记录要求

如果实现需要偏离推荐技术栈或调整阈值，必须新增决策记录，至少包含：

- 决策背景；
- 选择方案；
- 被否决方案；
- 对数据契约、历史兼容和验收的影响；
- 回滚方式。

偏离不得削弱合规、可追溯、当时可知、策略独立和失败阻断要求。
