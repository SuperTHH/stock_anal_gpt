# 真实数据最小闭环设计

## 1. 文档状态

- 状态：已完成交互设计审批，等待书面规格复核
- 设计日期：2026-07-30
- 目标分支：`codex/real-data-minimal-loop`
- 适用范围：个人、非商业 A 股研究
- 报告性质：历史重建试点，不构成投资建议

本设计在现有行情采集、XBRL 财务事实内核、三个策略引擎、不可变报告发布器、
FastAPI 只读接口和 React 页面之上，补齐一条真实、可追溯、失败关闭的纵向闭环。
首批闭环只覆盖 30 只固定样本，不宣称代表全市场。

## 2. 已批准的产品决策

1. 试点样本固定为 30 只 A 股。
2. 样本采用分板块流动性抽样：沪市主板 8 只、深市主板 8 只、创业板 7 只、
   科创板 7 只。
3. 抽样基准日为 2026-07-22，以当日成交额降序选择，代码升序作为稳定平局规则。
4. 财务范围包括 2023、2024、2025 年度报告，2025、2026 年一季报，以及
   2021–2025 年官方分红记录。
5. 报告信息截止点为 `2026-07-22T21:30:00+08:00`。
6. 文件获取采用清单驱动的半自动方案：公开稳定入口自动逐份获取，受限入口转人工
   收件箱；不调用隐藏接口，不绕过验证码或限制。
7. 财务事实优先使用交易所 XBRL；仅在同一申报没有可用 XBRL 时使用巨潮 PDF。
8. 三个策略池独立计算、独立阻断。每个池至少需要 24/30 只样本拥有全部关键因子；
   候选自身的关键因子和来源链必须 100% 完整。
9. 策略池未达标时不发布该池排名，但可以发布缺失清单和质量状态；其他达标策略池
   不受影响。
10. 研究文案由版本化规则模板生成，不允许大模型依据不完整数据自由补写事实。

## 3. 当前基线

本机现有私有数据已经包含：

- 上交所证券主数据 2,309 条；
- 深交所证券主数据 2,892 条；
- 2026-07-22 Tushare 未复权日线 5,198 条；
- 行情 Raw Object、来源记录、Parquet 工件和成功检查点。

当前私有状态库只应用了前五个迁移，尚未建立财务申报与报告快照表。当前没有真实
XBRL、PDF 财务事实、公司行动、分红、策略候选或已发布真实报告。前端非演示模式会
读取最新已发布报告，因此闭环完成前应保持“暂无已发布报告”，不得自动回退到演示数据。

## 4. 时间语义

### 4.1 历史重建而非伪装成当日运行

首份真实报告是在 2026-07-22 之后采集和生成的历史重建。系统必须同时保存：

- `report_cutoff_at`：`2026-07-22T21:30:00+08:00`；
- `market_date`：`2026-07-22`；
- `generation_started_at`：实际运行时间；
- `known_at`：本次历史重建实际可读取本地工件的时间；
- `published_at`：报告实际发布到本地系统的时间；
- `is_historical_reconstruction`：`true`。

源文件可以在截止点之后被本系统采集，但其原始公开时间必须不晚于
`report_cutoff_at`。因此“何时公开”和“本系统何时采集”不能混为一个字段。

### 4.2 防止未来数据泄漏

进入因子或排名的记录必须同时满足：

- `published_at <= report_cutoff_at`；
- `effective_at <= report_cutoff_at`；
- `collected_at <= known_at`；
- `valid_from <= known_at`；
- 质量状态为 `VALID` 或可接受的 `DERIVED`；
- 未被截止点前已公开的可用更正版本替代。

2026-07-22 之后公开的半年报、更正、分红、公司行动或监管事件不得进入首份报告，
即使它们在历史重建时已经可以下载。

### 4.3 证券主数据的特殊处理

现有证券主数据在 2026-07-24 至 2026-07-25 才被采集。板块、代码和上市日期等稳定
字段可以用于构建历史重建清单，但必须保存实际采集时间。ST、退市风险、停复牌和调查
状态属于时变字段，不能用 7 月 25 日状态倒推 7 月 22 日；它们必须由截止点前的官方
状态或公告重建。无法重建时，该股票不得进入最终样本。

## 5. 范围

### 5.1 本轮包括

- 安全地升级现有本地 SQLite 状态库；
- 从真实行情与证券主数据生成固定的 30 只试点样本；
- 生成所需财报、分红、股本和公司行动的采集清单；
- 从批准的公开入口低频逐份获取文件；
- 支持可审计的人工收件箱；
- 导入真实交易所 XBRL；
- 在 XBRL 缺失时解析巨潮 PDF，并执行严格质量校验；
- 保存申报版本、更正链和四类时间；
- 计算真实派生财务指标、截止日总股本、市值和估值因子；
- 运行三个独立策略池及覆盖率门禁；
- 原子发布一份历史重建报告；
- 通过现有 FastAPI 和 React 页面展示真实结果、阻断状态和来源。

### 5.2 本轮不包括

- 全市场财务初始化；
- 五年全市场行情补录；
- 自动交易、仓位、目标价或买入指令；
- 商业媒体正文、雪球、股吧或东方财富内容；
- LLM 自动生成未经规则和来源约束的研究结论；
- 宏观新闻的完整自动采集；
- 2026-07-22 之后公开的信息；
- 对验证码、登录、403、429 或页面限制的规避。

## 6. 固定样本生成

### 6.1 输入

- 已发布并通过完整性校验的 2026-07-22 行情 Parquet；
- 上交所和深交所各自的官方证券主数据快照；
- 截止点前有效的 ST、退市、停复牌、调查和上市状态事实。

### 6.2 硬过滤

抽样前排除：

- 非 `.SH` 或 `.SZ` 的证券；
- 北交所、B 股、港股和非普通 A 股；
- ST、`*ST`、退市整理或明确退市风险；
- 2026-07-22 停牌或当日无有效成交；
- 上市不足 365 天；
- 处于重大立案调查且规则要求排除；
- 主数据身份冲突、缺失上市日期或无法还原截止日状态；
- 成交额、价格或代码质量异常。

### 6.3 配额与排序

按板块分组后，使用 `amount DESC, ts_code ASC` 排序并选取：

- `MAIN_SH`：8；
- `MAIN_SZ`：8；
- `CHINEXT`：7；
- `STAR`：7。

任一板块不足配额时整次样本生成失败，不从其他板块补位。样本一经发布即不可变，
后续采集失败不会自动换入下一只股票，因为换样会改变横截面排名基准。

### 6.4 样本快照

`PilotUniverseSnapshot` 至少包含：

- `universe_id`；
- `market_date`；
- `report_cutoff_at`；
- `algorithm_version`；
- 四板块配额；
- 有序 `ts_codes`；
- 每只股票的板块、成交额、选择名次和过滤证据；
- 输入行情与主数据的内容哈希；
- `manifest_hash`；
- `created_at`。

## 7. 采集清单

### 7.1 清单内容

每只样本股票需要：

- 2023、2024、2025 年度报告；
- 2025、2026 年一季报；
- 2021–2025 年每年的分红方案、实施结果和取消或更正记录；
- 截至 2026-07-22 的股本及影响总股本的公司行动；
- 用于硬过滤和风险模板的相关官方监管或审计事实。

仅定期报告即为 150 个预期申报项。分红与公司行动按实际公告数量展开。

### 7.2 清单项数据结构

`AcquisitionManifestItem` 至少包含：

- 身份：`item_id`、`universe_id`、`ts_code`、`document_kind`、
  `report_type`、`report_period`；
- 业务时间：`published_at`、`effective_at`、`report_cutoff_at`；
- 来源：`source_id`、`source_url`、`discovery_method`；
- 版本：`content_hash`、`version`、`supersedes_id`；
- 状态：`status`、`quality_status`、`error_code`、`attempt_count`；
- 本地工件：`raw_object_hash`、`attachment_name`、`content_type`；
- 审计：`collected_at`、`terms_reviewed_at`、`created_at`、`updated_at`。

状态只允许：

`PLANNED`、`DISCOVERED`、`DOWNLOADED`、`VERIFIED`、`INGESTED`、
`AWAITING_MANUAL`、`REJECTED`。

状态转换必须幂等。相同身份和相同内容哈希不得生成重复事实。

## 8. 文件获取与人工回退

### 8.1 来源优先级

1. 上交所或深交所公开 XBRL；
2. XBRL 不存在时的巨潮公开定期报告 PDF；
3. 自动访问受阻时由用户从同一批准来源下载到人工收件箱。

XBRL 可用且通过验证时，禁止读取同一申报 PDF 来替换 XBRL。PDF 可以作为审计附件，
但不得产生第二套可排名事实。

### 8.2 自动访问规则

- 只访问 `SourcePolicy` 明确批准的域名、协议和用途；
- 只使用公开页面上明确可见的列表或下载链接；
- 禁止调用隐藏接口、逆向参数、伪造会话或规避限流；
- 单线程、低频、有限重试；
- 401、403、429、验证码、登录墙或条款不明确立即停止该来源；
- 保存最终 URL、响应时间、内容类型、长度、ETag 或 Last-Modified（如有）；
- 先验证扩展名、MIME、大小、压缩包和 XML/PDF 安全性，再写 Raw Store。

自动采集器不得把网站失败静默转换为其他未批准来源。

### 8.3 人工收件箱

人工下载文件必须附带机器可读侧车元数据：

- 清单项 ID；
- 真实官方来源 URL；
- 证券代码；
- 文档类型与报告期；
- 官方发布时间；
- 实际下载时间；
- 文件名与 MIME。

文件名本身不能证明身份。系统必须核对清单项、来源策略、文件哈希、报告期、交易所和
截止时间。人工文件与自动文件走相同的安全扫描、Raw Store、解析、版本和质量流程。
无法确认来源或官方发布时间的文件标记为 `REJECTED`。

## 9. 财务事实、分红与公司行动

### 9.1 XBRL

复用现有离线 Arelle 边界、SafePackageMaterializer、不可变 Raw Store、申报仓储和
时间点查询。新增生产 QName 映射必须版本化，并覆盖试点所需的最小事实集合。

### 9.2 PDF

PDF 提取事实初始状态为 `UNVERIFIED`。只有在以下检查全部通过后才可变为 `VALID`：

- 报告期、报告类型和证券身份一致；
- 单位和币种明确；
- 资产负债表恒等式在容差内成立；
- 现金流小计与总计勾稽通过；
- 同期重复事实一致或已生成冲突记录；
- 关键字段完整；
- 表格页、脚注页和更正关系可追溯。

任何 XBRL/PDF 冲突均优先保留 XBRL 作为展示事实，同时把冲突标记为质量阻断；冲突
未解决时相关股票不得进入依赖该事实的策略池。

### 9.3 更正

更正文件不得覆盖旧原件、旧事实或旧报告。新申报使用 `supersedes_id` 指向被替代版本。
时间点查询在更正公开之前返回旧版本；更正公开且可用之后返回新版本；更正公开但不可用
时不允许回退到已被替代的旧值。

### 9.4 截止日总股本

截止日有效总股本由最近一期可用股本事实，加上截止日前已公开且已生效的送转、配股、
回购注销等公司行动推导。缺少股本基准或公司行动链时，不估算市值，依赖市值的低估值
因子标记为数据不足。

## 10. 派生指标

最小真实事实集合应支持：

- 营业收入；
- 归母净利润；
- 扣非归母净利润；
- 经营活动现金流净额；
- 资本开支或可审计的资本开支代理；
- 总资产、流动资产、现金及现金等价物；
- 总负债、有息负债、流动负债；
- 归母权益；
- 毛利润或营业收入与营业成本；
- 利息费用；
- 期末总股本；
- 分红金额、每股分红、股权登记日和实施状态。

派生指标至少包括：

- ROE、ROIC；
- 年度及一季度收入同比；
- 年度及一季度扣非利润同比；
- 经营现金流/净利润；
- 毛利率及三年稳定性；
- 资产负债率、有息负债率、现金债务覆盖；
- 自由现金流和自由现金流收益率；
- 截止日市值、PE、PB；
- 已公告股息率、派息率、自由现金流覆盖；
- 连续分红年限和分红削减标记。

每个 `DerivedFinancialMetric` 必须记录公式版本、输入事实 ID、计算时间、截止时间和
质量状态。除零、负分母、单位冲突、缺失事实或不可用更正均不得生成误导性数值。

## 11. 三个独立策略池

### 11.1 质量成长合理估值

版本：`quality-growth-pilot-v1`。

关键因子：

- ROE；
- ROIC；
- 收入增长；
- 扣非利润增长；
- 现金流质量；
- 毛利率稳定性；
- 负债水平；
- PE/PB 试点样本分位。

### 11.2 低估值价值

版本：`deep-value-pilot-v1`。

关键因子：

- PE；
- PB；
- 自由现金流收益率；
- 试点横截面和可用历史分位；
- 资产质量；
- 负债与现金覆盖；
- 周期位置可用性；
- 价值陷阱风险。

首版样本通常无法形成每个行业至少 20 只的比较组，因此明确使用 30 只试点样本作为
市场回退范围，并在因子明细中显示 `normalization_scope=pilot_universe`。页面不得显示
“行业排名”。

### 11.3 稳定高股息

版本：`stable-dividend-pilot-v1`。

关键因子：

- 2021–2025 连续分红；
- 截止点前已公告股息率；
- 派息率；
- 自由现金流覆盖；
- 负债和利息覆盖；
- 分红削减风险。

预测股息或截止点后公告的分红不得进入得分。

### 11.4 独立发布门槛

`PoolReadiness` 至少包含：

- `strategy_type`；
- `universe_size=30`；
- `eligible_count`；
- `complete_factor_count`；
- `coverage_ratio`；
- `required_coverage_ratio=0.80`；
- `status`：`READY` 或 `BLOCKED`；
- 缺失股票、缺失因子和阻断代码；
- 策略与因子版本。

只有 `complete_factor_count >= 24` 时该池才可以排名。候选自身所有关键因子的事实和时间
链必须完整。三池不合并总分，也不跨池直接比较。

## 12. 可解释研究文案

入选理由、风险、观察条件和失效条件由版本化规则模板根据真实因子生成。例如：

- ROIC 与现金流质量同时处于试点样本高分位时生成质量理由；
- 低 PE 但现金流覆盖恶化时生成价值陷阱风险；
- 连续分红但自由现金流覆盖低于阈值时生成削减风险；
- 核心因子连续两个报告期跌破规则阈值时生成失效条件。

每条文案保存模板 ID、模板版本、触发因子和来源记录 ID。催化剂只有在存在截止点前
已验证官方事件时才显示；否则使用“暂无可验证官方催化剂”，不得生成推测性事件。

## 13. 运行编排

新增单一历史重建命令，按以下阶段执行：

1. 备份并升级状态库；
2. 校验行情、证券主数据和来源策略；
3. 生成或读取不可变试点样本；
4. 生成采集清单；
5. 对可自动获取项逐份处理；
6. 扫描人工收件箱；
7. 导入 XBRL、PDF、分红和公司行动；
8. 以截止点和实际 `known_at` 装配财务事实；
9. 计算派生指标；
10. 运行硬过滤和三个独立策略池；
11. 计算各池覆盖率；
12. 原子发布报告和最新指针；
13. 输出结构化运行摘要和人工待办。

各阶段必须有稳定检查点。中断后复用相同清单和内容哈希继续，不能重新抽样或重复下载
已验证文件。

## 14. 原子报告、API 与 UI

报告快照新增：

- `universe_id` 与 30 只样本摘要；
- `is_historical_reconstruction`；
- `report_cutoff_at`、`known_at`、`generation_started_at`；
- 三个 `PoolReadiness`；
- 人工待办与缺失摘要；
- 各数据域状态；
- 来源、事实、因子、策略和模板版本。

UI 必须：

- 显示“真实数据 · 30 只试点样本 · 历史重建”；
- 显示报告截止时间和实际生成时间；
- 明确排名只在试点样本内有效；
- 对 `BLOCKED` 策略池显示覆盖率、缺失项和阻断原因，不显示空排行榜伪装成功；
- 对候选显示真实名称、代码、因子明细、来源和失效条件；
- 真实模式绝不加载 `demo.ts`；
- 保留演示模式的明确水印和独立 URL 参数；
- 数据域失败时继续展示上一份已发布报告，并标记为过期。

API 和 UI 只读取已发布报告快照，不直接读取 Raw、Parquet、临时结果或未完成的清单项。

## 15. 失败处理

- 状态库升级失败：保持原库不变，停止运行；
- 样本不足或截止日状态无法验证：停止整个闭环；
- 网站出现 401/403/429/验证码：对应项转 `AWAITING_MANUAL`，停止该来源自动访问；
- 文件身份、MIME、安全或来源失败：标记 `REJECTED`；
- XBRL 解析失败且存在获准 PDF：进入 PDF 回退；
- XBRL 与 PDF 冲突：保留审计记录并阻断依赖事实；
- 单池覆盖不足：仅阻断该池；
- 三池全部阻断：不发布候选榜，但发布质量报告与待办；
- 报告发布前失败：不移动 latest 指针；
- 报告发布后 UI 读取失败：返回明确错误，不回退演示数据。

## 16. 安全与合规

- Token 只从 `.env` 或本地密钥存储读取，不进入日志、命令参数、报告或 Git；
- `.env`、`data/`、SQLite、Parquet、Raw、附件和真实报告保持 Git 忽略；
- CI 不访问真实网站，不接收 Token 或真实附件；
- 所有来源访问必须先通过 `PolicyGuard`；
- 不保存商业财经媒体正文；
- 巨潮文件仅用于个人非商业研究；
- 遇到限制立即停止，不切换到条款不明来源；
- 来源条款复核日期进入报告质量页。

## 17. 测试策略

### 17.1 CI 自动测试

只使用明确标注的虚构夹具，覆盖：

- 四板块配额、排序、平局和硬过滤；
- 样本不足时失败且不跨板块补位；
- 清单身份、状态机和幂等性；
- 截止时间、实际采集时间和更正版本；
- XBRL 优先、PDF 回退和冲突阻断；
- 总股本与估值依赖链；
- 派生指标的公式和异常分母；
- 三个策略池 24/30 门槛；
- 单池阻断不影响其他池；
- 原子报告和 latest 指针；
- UI 真实模式不加载演示数据。

CI 无网络、无真实 Token、无真实附件。

### 17.2 本地集成测试

使用临时数据库和脱敏清单验证：

- 旧状态库迁移；
- 断点续跑；
- 自动项与人工收件箱汇合；
- 写工件后中断的恢复；
- 更正公开但不可用时的失败关闭；
- 发布失败保留上一报告。

### 17.3 真实数据验收

真实数据验收只在本机执行并输出聚合摘要，至少核对：

- 样本恰好 30 只且配额为 8/8/7/7；
- 样本清单哈希稳定；
- 150 个定期报告清单项的状态分布；
- 分红、股本和公司行动覆盖；
- XBRL/PDF 使用数量及回退原因；
- 财务事实和派生指标数量；
- 三个池各自覆盖率与状态；
- 候选的来源链、截止时间和模板版本；
- 报告工件哈希与 SQLite 指针一致；
- API 和 UI 展示同一报告 ID；
- Git 工作区没有真实数据或附件。

## 18. 验收标准

闭环完成必须同时满足：

1. 现有 2026-07-22 行情和证券主数据在迁移后仍可校验；
2. 固定样本为 30 只，配额和排序可复现；
3. 每个清单项都有状态、来源和时间审计；
4. 自动获取不触碰隐藏接口、验证码绕过或未批准来源；
5. XBRL 优先级和 PDF 回退可由测试证明；
6. 更正不覆盖历史版本，时间点查询无未来泄漏；
7. 估值只使用可验证的截止日股本；
8. 三个策略池独立，覆盖率门槛精确为 80%；
9. 未达标策略池没有候选排名；
10. 候选研究文字可追溯到模板和真实因子；
11. 报告原子发布，失败保留上一版本；
12. 非演示 UI 展示真实历史重建标识、样本边界和来源；
13. 全量 Python、Ruff、前端测试、前端生产构建和双平台 CI 通过；
14. 真实附件、数据库、Parquet、Token 和候选结果未进入 Git。
